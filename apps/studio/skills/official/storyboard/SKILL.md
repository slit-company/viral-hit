# Storyboard director

Use for reference-led or original multi-shot work, from general films and image sequences to a specialized character introduction, explainer or product story. Do not assume a channel, narrator, aspect ratio, model, hook/CTA structure or duration.

1. Resolve the active project and read its assets, recipe catalog/digests and existing storyboard through the tools. Import owned media before using it. The reference sampler extracts five frames; that is not a complete cut analysis or proof of inspection. Inspect relevant source frames/playback and listen when needed. Record missing coverage honestly.
2. Author a storyboard with scope, intent, source observations and ordered shots. Each observation binds a project assetId and sha256 and labels its basis as observed, inferred or proposed. Use time ranges for video/audio when available. Shot direction and preserve/change/avoid fields record the transformation; never invent a visual observation from a filename or job success.
3. Use viral_hit_storyboard save with the read expectedRevision (zero creates). A shot can use an existing asset or an independently authored recipe with its exact digest, values and materializing outputNodeId. Recipe values are the actual inputs: translate the desired direction into that recipe's declared parameters yourself and show material choices. The service does not inject prose into model prompts or choose a provider.
4. For authorized generation, call generate for each chosen shot with a fresh requestId. Read the board's actions/runs. On uncertain transport outcome, read or resume the SAME requestId; do not invent another request to retry a potentially paid job. Changed recipe or adapter configuration must be resolved through the existing run recovery workflow. A new requestId means a deliberate new attempt. Generating an alternative does not replace accepted media.
5. Inspect actual output and compare it to the shot's referenced observations, requested changes, timing and identity. Accept a succeeded generation requestId or an existing assetId+sha256 with truthful review notes and source inPoint. Notes are a caller's review record, not machine-certified quality. Changed shot/reference context invalidates acceptance. For a reference remake, retained stills alone do not establish motion, audio or whole-source fidelity.
6. After all current shots are accepted, assemble with a stable requestId. This prepares an ordinary editable-sequence run, including shot captions and explicitly selected soundtrack ranges. Wait for that run to succeed. Use the existing run attachment operation with the latest timeline revision; a conflict needs a fresh timeline review. The sequence appends and remains editable. Export through the existing editor, inspect/listen to the actual result and report remaining uncertainty.
7. Publication remains a separate reviewed operation with the chosen destination and existing authorization rules. No publication follows automatically from storyboard acceptance.

Browser authoring is not yet available. Use MCP or the documented HTTP/CLI surface. A plan's JSON contains project-local asset IDs; it does not bundle media or migrate a board between installations. Saved source observations and accepted results are retained as revisions. The service reserves exact execution plans before enqueue so a restart resumes original work.
