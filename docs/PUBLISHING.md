# Publishing implementation status

YouTube transport exists under `core/publishing/`; it is not connected to a publishing UI, HTTP/MCP command or background publisher yet. No real account upload has been performed. Meta/Instagram remain pending. A generation receipt or local export is not a published post.

The transport verifies the OAuth channel, then uses the same credential to create a resumable session. Privacy, audience, synthetic-content disclosure and subscriber notifications are explicit. Scheduled time is checked again after account discovery. It accepts only the expected HTTPS Google upload endpoint and sends fixed 8 MiB chunks (except the final chunk), with provider-reported offsets. Session probes can recover the original video receipt after a missing final acknowledgement. Expiration and unknown outcomes never automatically create another session. Upload acceptance, processing and privacy remain distinct fields.

The implementation follows Google's [resumable-upload protocol](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol), [video insertion contract](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert), [video metadata/status contract](https://developers.google.com/youtube/data/reference/rest/v3/videos) and [channel identity lookup](https://developers.google.com/youtube/data/reference/rest/v3/channels/list). Reads have bounded JSON bodies; fetches have a 30-second deadline and redirects disabled. Credentials/session URLs are not included in diagnostic errors.

Ten tests cover metadata/scheduling, credential consistency, wrong/ambiguous channels, hostile URLs, invalid ranges/chunks, expired sessions, rejection versus unknown outcomes, response size/cancellation, and partial/final response loss. The local HTTP test transmits actual bytes, deliberately loses acknowledgements, resumes one session and verifies the received SHA-256. It emulates the provider protocol; it does not establish Google acceptance, OAuth readiness, channel permissions, quota availability or real public visibility. All 524 studio source tests and type/architecture checks pass.

Before exposing publishing, implement the [durable intent boundary](architecture/003-publishing-intents.md): account connection/credential isolation, project-owned export hash/size pinning, approval revision, intent/session persistence before side effects, lease/recovery state, public receipt projection, worker, shared UI/HTTP/MCP operations and an authorized live test. reference pipeline's separate staging/publication/recording stages inform this boundary; its brand-specific account data and policies are not copied.
