# Publishing implementation status

YouTube transport, a connector, a durable SQLite publication store, a single-step worker, retained project-media storage and a workspace YouTube account service exist under `core/publishing/`. The workspace account service is exposed at `/connections` through trusted HTTP account operations and a Google callback. Project publication drafts, revision-bound approval, retained-video preview, safe delivery observations and a separate publication worker are now exposed through shared UI/HTTP/MCP/CLI application operations. No real account upload has been performed. Instagram local-upload transport, connector and a separately fenced final publish stage are fixture-tested; Instagram browser account connection and explicit Page selection are implemented; Instagram publication admission, retained preview and approval/delivery UI are integrated. Local Instagram scheduling is implemented; images/carousels and authorized live verification remain pending. A generation receipt or local export is not a published post.

The transport verifies the OAuth channel, then uses the same credential to create a resumable session. Privacy, audience, synthetic-content disclosure and subscriber notifications are explicit. Scheduled time is checked again after account discovery. It accepts only the expected HTTPS Google upload endpoint and sends fixed 8 MiB chunks (except the final chunk), with provider-reported offsets. Session probes can recover the original video receipt after a missing final acknowledgement. Expiration and unknown outcomes never automatically create another session. Upload acceptance, processing and privacy remain distinct fields.

The implementation follows Google's [resumable-upload protocol](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol), [video insertion contract](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert), [video metadata/status contract](https://developers.google.com/youtube/data/reference/rest/v3/videos) and [channel identity lookup](https://developers.google.com/youtube/data/reference/rest/v3/channels/list). Reads have bounded JSON bodies; fetches have a 30-second deadline and redirects disabled. Credentials/session URLs are not included in diagnostic errors.

The generic intent binds account, destination, connector version, asset hash/size and metadata to one approved digest/revision. Edits invalidate approval. A stable request key prevents duplicate intent creation. Session URLs and raw connector receipts are excluded from its browser projection. The worker persists `starting` before creating a session and persists the returned checkpoint in a separate commit before transmitting media. A crashed `starting` action stays uncertain. Known sessions recover from provider-reported progress, and accepted receipts can be inspected after source media is removed.

Local stop prevents subsequent local work; it does not delete an uploaded video or cancel a remote schedule. The old lease deadline remains a quarantine for in-flight requests, so immediate reconciliation cannot race a previous writer. Reconciliation queries the original remote identity; continuing an incomplete upload requires a separate resume. An unknown creation without a stored identity cannot automatically be retried. Runtime/credential resolution remains a server boundary that must honor cancellation. The project-media implementation now resolves actual local project memberships, retains verified bytes and supplies bounded integrity-checked ranges to the executor.

The account service adds server-only `oauth4webapi` 3.8.8 with no runtime dependencies; no browser modules were added. Media transmission uses fixed 8 MiB chunks and one bounded action per lease. Store JSON is limited to 128 KB per value; repeated unchanged polls update the existing row rather than append idle events. [Project-media retention](PUBLICATION-MEDIA.md) streams full-hash verification during preparation, stores indexed block hashes and checks only the blocks touched by a later read. Source edits/deletion cannot replace approved bytes. Large synthetic-file measurements are recorded in [performance](PERFORMANCE.md); they are not live upload benchmarks.

Publishing protocol tests cover metadata/scheduling, credential consistency, project/revision boundaries, redaction, lease fencing, recovery, phase separation, wrong/ambiguous channels, hostile URLs, invalid ranges/chunks, expired sessions, bounded responses, and partial/final response loss. Media coverage adds real project image/audio/video retention, foreign membership, deleted projects, changed source content, unaligned ranges, corruption, symlinks, cancellation, concurrent preparation, orphan recovery and missing integrity records. A project integration sends the retained bytes of a real FFmpeg-generated video through the YouTube connector's fetch fixture after deleting the source; its received SHA-256 matches the approved pin.

The local HTTP transport test transmits actual bytes, deliberately loses acknowledgements, resumes one session and verifies SHA-256. A separate connector/executor test reopens a real SQLite database between steps and reproduces partial/final acknowledgement loss through a fetch fixture with exactly one session creation. These do not establish Google acceptance, live OAuth readiness, channel permissions, quota availability or real public visibility.

The [application boundary](architecture/008-publication-application.md) now connects safe provider-specific receipts, worker scheduling and shared UI/HTTP/MCP/CLI operations. An authorized live provider test is still required. Retained-media lifecycle and cleanup also remain to be defined. reference pipeline's separate staging/publication/recording stages inform this boundary; its brand-specific account data and policies are not copied.

## Workspace YouTube account service

`openYouTubeAccounts()` now owns PKCE/offline consent attempts, one-time browser-bound callbacks, verified channel identity, encrypted durable tokens, reconnect/disconnect and leased refresh across processes. Reconnect preserves the original channel. A stale callback/refresh cannot restore a disconnected account; late 401s cannot expire a newer token. Revoked grants require reconnection, while temporary failures and invalid client configuration retain the grant and back off. The real connector can use this service without exposing tokens. See [account architecture](architecture/004-publishing-accounts.md).

Operator settings are `VIRAL_HIT_GOOGLE_CLIENT_ID`, `VIRAL_HIT_GOOGLE_CLIENT_SECRET` and `VIRAL_HIT_GOOGLE_REDIRECT_URI`. The registered callback path is `/api/app/publishing/youtube/callback`. Configure this exact path on the same origin used to open the studio and register the full URL in the Google Cloud web application client. Use HTTPS except loopback development. Do not infer the callback from a request Host header. The HTTP layer creates a private per-attempt browser-binding cookie and enforces the shared workspace trust checks. See [browser account connections](architecture/007-publishing-account-http.md).

The default account directory is `data/publishing-accounts` under the configured data root. Back up its database and `workspace.key` together. An optional `VIRAL_HIT_PUBLISHING_KEY` must contain exactly 64 hexadecimal characters; changing or losing the key makes existing credentials unreadable. The database fingerprint rejects mismatched keys. Account service configuration does not connect an account, approve a post, or start a scheduler. Disconnect currently invalidates local access; it does not revoke the upstream grant or cancel a remote video.

Twenty-one added account tests use real SQLite stores and deterministic protocol fixtures, including a publication worker whose rejected cached token is refreshed before exactly one session creation. No live consent or upload was performed.


## Connecting from the studio

Open **Publishing connections** in a workspace header, or visit `/connections`. With valid operator settings, **Connect YouTube** starts Google consent in the same tab. The callback returns to the connection list; access/refresh tokens never pass through that page. A verified channel shows its name, channel ID and stored connection status. **Renew access**/**Reconnect** preserve the original channel. To add a different channel, use **Connect YouTube**.

**Disconnect** requires a second explicit action in the account card and a current account revision. It clears local credentials and invalidates pending reconnections, including when Google configuration has been removed. It does not revoke the Google grant, delete remote videos or cancel schedules. Configuration readiness is separate from stored account status; a connected row is not a guarantee that a later provider call will succeed.

`GET /api/app/publishing/accounts` requires the workspace request header even for reads; `POST` additionally requires trusted same-origin JSON. Actions are `{action: "connect", reconnect?: {accountId, revision}}` and `{action: "disconnect", accountId, revision}`. OAuth initiation is a browser operation because the binding is an HttpOnly cookie. Non-browser agents must not fabricate a completed connection; publication operations use stored account IDs through shared services.

Missing or mismatched operator settings disable new consent with an explanatory state. Configure settings outside the repository, restart the server, and refresh the page. No client secret entry is exposed in the browser. The studio remains a single-operator workspace: request-header/Origin checks are CSRF defenses, not multi-user authentication. Hosted installations need access control around the workspace before exposing account management.


## Prepare, review and deliver

Open **Publish project** in a project header, or `/publish/<projectId>`. Select a connected YouTube channel and a local MP4/WebM asset. Enter the title, description, visibility, audience and synthetic-content disclosure. Optional schedule/details include the local-time publication date (with the browser timezone shown), tags, category and subscriber notification. Scheduled delivery requires private visibility and a future time. Save a draft to retain verified original bytes; no upload starts at this step.

The review card plays the exact retained file, including after the source file is removed. Its URL binds the publication digest; a revised draft invalidates the old preview. Review the channel, metadata and visibility, then check the confirmation and choose **Approve upload**. An unavailable preview or disconnected channel disables approval in the browser. The application rechecks account, retained media, revision, digest and configuration. Editing a draft increments its revision and clears approval. A worker that already claimed an approved publication prevents further editing.

`pnpm dev` and `pnpm start` launch a dedicated publication worker alongside generation. It processes one bounded action per lease and polls idle queues once per second. It opens OAuth lazily, so an empty or unconfigured workspace stays offline. Shutdown aborts the current step and awaits cleanup. `pnpm --dir apps/studio publication:worker` runs that worker separately. Connected credentials and valid configuration do not themselves authorize any video.

Queue status distinguishes bytes received, processing, private/unlisted readiness, scheduled delivery and observed public visibility. **Stop local delivery** fences local work; it cannot undo an already sent request or cancel a YouTube schedule. **Check original upload** performs read-only reconciliation of a stored remote identity. Only a confirmed **Continue original upload** resumes an incomplete session. Unknown session creation never retries automatically.

`GET/POST /api/app/projects/<projectId>/publications` require the workspace header; POST also requires trusted JSON capped at 32 KB. Actions are `create`, `revise`, `approve`, `stop`, `reconcile`, and `resume`; their strict schema is in `core/publishing/requests.ts`. Creation takes an asset/account ID and metadata, with a stable `requestKey`. Approval requires `publicationId`, `expectedRevision`, `expectedDigest`, and `confirmed: true`. Resume also requires confirmation. Replaying the same creation request returns its current record even after a revision/source deletion. Reusing its key for different content conflicts.

MCP tools `viral_hit_publication_list` and `viral_hit_publication_change` use the same application service and project targeting. Agents must obtain human authorization of the reviewed revision before approve/resume. CLI equivalents are `pnpm --dir apps/studio publication --project ID list` and `pnpm --dir apps/studio publication --project ID change < request.json`. All return the public projection, excluding private sessions, credentials, lease tokens and arbitrary provider fields.

Native video playback uses a separate same-origin media read, because a video element cannot attach the workspace header. It rejects foreign Origin/Fetch-Metadata requests, returns `Cross-Origin-Resource-Policy: same-origin`, supports single byte ranges, and reads only project-scoped retained bytes for the exact digest. It is not a public media-sharing URL. These browser controls do not replace deployment authentication.

The shared worker commits `publishing` before the final POST and never automatically repeats an ambiguous publication. ## Connecting Instagram

Configure the four Meta settings described in [decision 010](architecture/010-instagram-accounts.md), using a Facebook Login for Business User access token configuration with the four documented permissions. On Connections, choose Connect Instagram, complete Meta consent, then review and select the Page-linked Instagram account. Reconnecting preserves both the Page and Instagram identity. Tokens stay encrypted on the server; choosing a destination does not upload or publish anything.

Account disconnect remains available if Meta configuration is removed. It clears local credentials and pending reconnects, while existing Instagram posts stay remote. Back up `data/publishing-accounts/instagram/accounts.sqlite` together with its sibling `workspace.key`. Live Meta consent and publishing have not yet been verified.


## Instagram project publications

Choose **Instagram** under Destination, select the explicitly connected account and a project MP4, then choose Reel or Story and the AI disclosure. Reels accept a caption; Stories do not forward a hidden Reel caption. Save pins the project-owned bytes and runs bounded FFprobe inspection on the same verified retained file descriptor. Neither user paths nor arbitrary URLs enter the probe process. Review the retained video and confirm **Approve & publish** to authorize upload and final publication of that exact digest/revision. Selecting or connecting an account does not authorize publication.

Admission checks measured duration (Reels 3–900 seconds, Stories 3–60), file size (300/100 decimal MB), H.264/HEVC and 4:2:0 video, progressive/unspecified field order, 23–60 FPS, maximum width 1920 and format-specific aspect bounds. One video and at most one AAC mono/stereo audio stream at up to 48 kHz are accepted. Known video bitrate above 25 Mbps is rejected. No automatic transcoding occurs. These checks follow the [Meta media reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media/), inspected on 2026-10-20. They do not prove closed GOP, VBR, edit-list/moov layout, audio bitrate compliance or provider acceptance; Meta remains authoritative. An anamorphic/rotated export should be normalized before submission. FFprobe must be installed or configured with `VIRAL_HIT_FFPROBE`.

Approval binds the local account UUID and original Instagram ID. The account store forbids changing the connected Page/Instagram pair during reconnect; the transport pins and rechecks that Page for each write. The durable final-publication fence and read-only recovery remain unchanged. Five successful `IN_PROGRESS` inspections, spaced by a 60-second poll delay, pause automatic processing checks with `processing-timeout`. The original receipt and its poll count survive. **Check original upload** can observe a later `PUBLISHED` result; a merely `FINISHED` result remains attention-required and never authorizes another POST. Transient transport errors back off without consuming the successful-observation count.

The safe view distinguishes YouTube delivery from Instagram container status. A lost final response can confirm `PUBLISHED` without a media ID; no permalink or missing ID is invented. Publishing-resume from a stopped/attention-required staged container, image/carousel posts, covers, tagging and analytics remain separate work. No live Meta consent, upload, public visibility or account permission acceptance is established by fixture tests.


## Scheduling Instagram

Set **Scheduled publication** in the Instagram form, review the displayed time and local timezone, then choose **Approve schedule**. The same optional `metadata.publishAt` accepts an ISO timestamp with an explicit offset through HTTP, MCP and CLI. Changing time creates a new revision and requires new approval. An elapsed draft cannot be newly approved. Leave the field empty for delivery after approval/processing.

This is a local studio schedule. The worker waits until ten minutes before the target to create/upload a container, then waits until the approved time to send final publication. Meta containers expire after 24 hours, so days-away reservations stay local. Keep the studio running with an accurate clock. The earliest publication time is enforced; processing, connectivity or downtime can delay delivery, and an already-approved reservation resumes when the studio returns. No exact-time SLA is implied. Use **Edit draft** before uploading begins to reschedule, or **Cancel delivery** to cancel a still-local reservation. Started/ambiguous operations retain their original identities and never silently create another post. See [phase timing](architecture/011-publication-phase-timing.md).
