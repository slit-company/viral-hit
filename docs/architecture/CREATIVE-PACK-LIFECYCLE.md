# Creative-pack release lifecycle

The composition service owns release identity and explicit partial completion; each recipe, skill and character library still owns its mutations. Updates retain the incoming archive, review every affected current definition and apply additions plus explicitly selected replacements. Dropped entries and unselected custom definitions stay available. Character replacement is a whole-definition, revision-checked operation in the character library after verifying reference bytes. Nothing runs or publishes during lifecycle.

Before the first write, the caller pins an inspection digest covering the active release revision, current definitions, reserved IDs and affected pack memberships. Each selected mutation then uses that library's captured digest/version. A concurrent edit can stop a later step after earlier steps succeed: return `complete: false` and exact item results, retain the previous active release, and require a fresh review of the same archive. Already matching items are reused. Do not retry unknown or partial outcomes blindly or claim a distributed transaction. Concurrent releases compare the active head revision again at completion.

Release metadata uses a managed SQLite overlay over existing immutable JSON completion records. Legacy files are never rewritten. Each new successful release stores one immutable manifest keyed by digest; image bytes remain in the existing content-addressed reference store. The active head is a revision-checked pointer. Historical manifests remain exportable by digest, including after removal. Metadata growth is capped at 64 MiB; there is no polling, archive cache or new dependency.

Removing a creative pack removes its active listing and retains its releases and all library entries. These entries can be reused or independently maintained elsewhere; deleting shared content is not inferred from removing a bundle. UI review states this explicitly. Full purge/garbage collection is outside this operation.

HTTP streams archives and accepts only validated action metadata, with no caller-provided host path. MCP and CLI use the same application service. UI shows both definitions, incoming images, previous-reference links, selection reset, partial state and historical downloads. Tests must cover legacy overlays, exact historical export, stale review, current-state races, partial recovery, preserved edits/queued work and trusted HTTP boundaries.
