# Optional speech recognition and portable transcripts

`core/transcripts/` owns a provider-independent, versioned transcript result and subtitle serialization. Results identify the exact project media, selected source-time range, recognition engine/model and estimated segment timings. They are machine estimates for review, not verified observations or a storyboard's acceptance record. They live in the existing durable job output; this feature adds no transcript database or execution engine.

An independently installed `ext.whisper-transcribe` adapter lives in `extensions/whisper/`. It reads declared project video/audio through the existing bounded media context, decodes a selected range to mono 16 kHz PCM and runs an operator-installed whisper.cpp CLI/model. No model downloads, package installs or daemon start happen when a recipe is inspected, installed or discovered. Code/configuration are pinned by the existing adapter wrapper; CLI and model hashes are additionally verified by the implementation. Dynamic libraries and FFmpeg installations remain operator-managed.

Admission pins source bytes. Submission records a stable request identity; polling performs bounded local work and returns transcript JSON plus standard caption/media clip specifications. Worker restart after success reads its stored result. Interruption before successful poll persistence can rerun local recognition. Cancellation waits for child closure before private-file cleanup. There is no paid/remote mutation to reconcile.

Portable recipes bind the same selected asset into the detector and existing `editor.sequence` step. Caption outputs are ordinary separate clips. A caption track may be empty when recognition yields no words; visual/audio source tracks still require clips and sequence inspection still requires a playable visual. Audio sources can use an independently selected image as that visual. Attachment appends at the current timeline end through the existing revision-checked command, so existing edits are preserved.

The Runs preview validates the public transcript contract, offers the original media and segment ranges, and exports SRT with times relative to the selected range. It never treats extension output as code or automatically accepts/publishes the result. Other installed engines can emit the same contract without changing the app. Source tests must cover invalid/out-of-range timing, no-speech output, immutable source/configuration checks and cancellation; real local model execution and editable browser/server output are recorded separately from protocol fixtures and broad accuracy claims.
