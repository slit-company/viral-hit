# Managed executable runtime packages

`core/runtime-packages/` owns portable, bounded JSON packages with complete generation-provider, execution-adapter and publishing-connector manifests plus self-contained source modules. Packages carry general/specialized scope and author/version metadata. Data-only creative packs and skills never install executable code. The existing three runtime owners still validate and execute their own contracts.

Inspection parses every manifest, checks source hashes and synchronous schemas without importing code or contacting providers. It exposes complete source/definitions and declared environment names, never environment values. Operators explicitly trust the reviewed source on mutation. This is trusted server code with host privileges, not a sandbox or signature verification. Dependencies must already be bundled or supplied by a separately managed external engine; there are no install scripts, shell commands, package-manager calls or automatic downloads.

Managed storage retains immutable release documents and revision-checked active pointers in SQLite. One transaction compares the reviewed catalog, checks identity/capacity and publishes the new release or removes its active pointer. Operator directories remain separate and cannot be overwritten. Conflicting runtime/model identities are rejected. Historical export restores the exact normalized source/manifest package; restoring requires normal review of that historical package against current state.

Runtime loaders consume a process-lifetime managed snapshot alongside existing operator configuration. Installation, update and removal change desired state; app, MCP and workers must restart together to activate it. Already loaded processes retain their original bytes. Existing adapter/configuration fingerprints and publication runtime versions continue to fence queued or running work after restart; new code never migrates an old job. Retained releases permit explicit restoration of the original runtime. Managed provider task identities now pin source/model/declared configuration and retain the original upstream task ID; a mismatched status check fails before importing source. Untracked operator tasks require their original operator runtime. Restart is not a task migration protocol.

Storage bounds: at most 16 entries per package, 12 MB serialized input, 8 MB module source per package, 32 active entries and 8 MB source per runtime kind across managed packages, 64 package identities and 128 MiB retained documents. Each owner keeps its existing per-module and manifest bounds. No daemon, polling or automatic garbage collection. HTTP/MCP/CLI share one service; loading or inspecting packages executes no source. Browser tooling is a transport over that same lifecycle, not another package manager.
