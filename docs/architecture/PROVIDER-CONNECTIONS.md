# Installed-provider connections

Providers may opt in with `configurationDelivery: "request"`. Their existing `environment` declaration becomes the allowlist of required settings passed as `request.configuration`; environment values take precedence over encrypted workspace values. Legacy modules continue reading environment variables, and their runtime digest serialization stays unchanged.

`core/generation-providers/installed/credentials.server.ts` owns the private AES-256-GCM store. Files use per-provider authenticated context, a separate 32-byte workspace key, private modes, no-follow checks, revision comparisons, an exclusive write lock and atomic replacement. The directory is local server state, never project/export state. A missing key with existing ciphertext fails closed. Back up the key and sealed files together; they are not an external key-management service. After a server crash during a write, a leftover lock deliberately requires operator inspection/removal.

`connections.server.ts` owns allowlisted mutations and optional connection checks. The HTTP route validates same-origin workspace mutation headers, bounds/parses input and returns metadata only. The UI uses SEED Action and SEED TextField and never imports server modules. Saving keys does not test authentication. `connectionTest: true` permits an explicitly invoked, bounded `testConnection({ configuration, signal })`; extensions are trusted operator code and must keep this check read-only. Normal diagnostics never imports executable modules or makes provider requests.

Generation submission now supplies `requestKey` derived from the already persisted generation ID. It cannot come from public caller parameters. Optional providers use it for upstream idempotency; core admission, receipts and recovery continue to own submission authorization. Installed providers receive only their declared configuration, and runtime digests include resolved values without exposing them. Credential changes fence old jobs; restoring the original values permits recovery. No process environment mutation, secret-bearing manifest or second job queue is introduced.

The Sume adapter is an optional self-contained bundle in `extensions/sume`. Studio gains no SDK dependency or model download. Provider-specific request shapes, signed uploads, catalog checks and job-result decoding live in that extension. Core retains references, persistent state, result storage and editing. Tests distinguish local transport/export verification from authenticated remote generation and quality evaluation.
