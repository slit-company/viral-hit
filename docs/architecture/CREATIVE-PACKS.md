# Creative pack composition boundary

`core/creative-packs/` composes the existing recipe, skill and character libraries. It owns the portable combined manifest, verified archive input/output, cross-library review and completion record. Its pure contract is safe for browser imports; filesystem/orchestration code is server-only. The existing library services retain their mutation and conflict rules. Shared tar code remains in `core/projects/bundles/`; there is no second extraction implementation.

A distributed transaction across SQLite databases and skill directories would introduce a second persistence authority and require invasive changes to every library. Instead, the composition service validates all input before writing, rejects known conflicts, performs each existing atomic library operation and reports partial completion if a later operation fails. It never claims success merely because a request returned. Replaying the same reviewed input reuses exact recipes, skills and characters. Conflicting contents always remain conflicts. A final immutable manifest record is published with a no-overwrite link after all operations succeed. Export uses that original manifest and content-addressed references, preserving the shared snapshot after local character edits.

Readers can observe installed items before the complete pack record. This is intentional and documented. An interruption does not remove successful items or roll back unrelated concurrent edits. Automatic execution of skills, paid generation, external publishing and installation of executable runtime modules are outside this boundary.


Remote sharing is stateless on the server: `fetch` downloads public HTTPS bytes to an atomic new file, then `inspect` and `install` operate on that retained file. The shared downloader pins public DNS, checks each redirect and bounds streamed bytes. The browser holds one Blob/File through review and installation; HTTP temporary downloads are removed when their stream closes or the request aborts. No long-lived remote cache, background cleanup process or URL-based installation state is introduced. MCP/CLI fetch intentionally returns `inspected: false`: a successful transfer is not a validated pack.
