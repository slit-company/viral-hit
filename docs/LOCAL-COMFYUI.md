# Native ComfyUI workflows

Open **Runs → Connections**, enter the HTTP(S) address of your own ComfyUI server, optionally **Check connection**, then **Save connection**. This enables `comfy.workflow` and `comfy.upload` independently of `COMFY_API_KEY`. A check only reads bounded `/system_stats`; it does not save, submit a job or verify installed models. Saving does not require a successful check, so temporarily offline servers can be configured. Use **Check server** on the selected recipe for node/input inspection.

Workspace settings persist in `connections.sqlite` under the shared data directory. The studio, worker and MCP process read the same settings without a restart when they use the same `VIRAL_HIT_DATA_DIR`. A browser URL refers to the machine hosting Viral Hit: `127.0.0.1` means that server, not a separate browser device. Credentials, query strings, fragments and redirects are rejected; authenticated endpoints remain unsupported. The URL is workspace configuration, never a URL supplied by a recipe.

For managed deployments, set `VIRAL_HIT_COMFYUI_URL=http://127.0.0.1:8188` on both server and worker and restart them. This environment override takes precedence and makes the UI read-only, including when the override is invalid. Removing it restores the saved workspace setting. Availability indicates configuration, not health. **Disconnect server** clears the workspace setting while retaining jobs and assets. Saves compare the last read revision so one tab or MCP process cannot silently overwrite another change.

To bring your own API-format graph into Runs, use the [workflow importer](EXTENDING.md#import-your-own-comfyui-graph). Specify the inputs you want to expose and the media output; the studio or CLI builds a portable manifest with the native execution and durable import stages. It works offline and does not install or run ComfyUI nodes during import.

`local-canvas` executes EmptyImage → SaveImage without model weights. `local-diffusion` uses an installed compatible checkpoint (for example SDXL), prompt encoders, a sampler, decoder and SaveImage. Choose the checkpoint filename actually installed on your server. Custom recipes may supply native API-format graphs and select one images/audio/gifs/videos output by node and index. Required models and nodes must already exist on ComfyUI. The `local-image-resize` recipe selects a local project image, uploads it as a separate durable input stage, and executes LoadImage → ImageScale → JoinImageWithAlpha → SaveImage, retaining the input transparency. Imported graphs can declare the same image parameter. Other input files must already be available on the server. Authenticated endpoints and automatic node/model installation are not implemented.

Use **Check server** in Runs to inspect installed node classes and current input/model choices before queueing. The [CLI/MCP check](EXTENDING.md#check-native-server-requirements-without-submitting-work) also works with unfilled inputs and never submits a workflow. It reports a schema snapshot, not successful generation.

The native protocol has different recovery semantics from Comfy Router. ComfyUI does not deduplicate prompt submissions by prompt_id. Viral Hit records its UUID and input fingerprint before submission, then looks for that original job in history and queue after a lost response. It never resubmits an uncertain native workflow. “Find original job” repeats this read-only reconciliation and resumes dependency-blocked materialization jobs if the original receipt is recovered. Cleared history remains uncertain. Cancel targets only the selected job through `/api/jobs/:id/cancel`; older servers without that route cannot confirm cancellation and there is no global interrupt fallback.

Completed files are bounded, downloaded through the configured ComfyUI bridge, published as hashed durable receipts, probed, materialized as project assets, and attached through the existing revision-checked timeline command. Redirects and path traversal are rejected. New native plans pin the normalized server URL fingerprint before enqueueing, even without an image input. Changing the address fences queued jobs, uploads, polling and ambiguous-response reconciliation; it never transfers a job to another server. Restore the original address, then use **Retry failed work** for a job rejected before submission or **Find original job** for an uncertain submission. Confirmed running jobs resume polling on the original address. An ambiguous submission stays uncertain across a connection change and cannot become a fresh submission through Retry. Legacy queued native jobs without a pinned connection are refused; create a new reviewed run. Legacy ambiguous submissions without a pin require manual recovery from their original server history. Already-confirmed legacy receipts retain their original connection fingerprint.

## HTTP and MCP settings

`GET /api/app/comfy-connection` returns `url`, `source` (`environment`, `workspace`, `none`), `editable`, `revision` and any environment-validation error. Mutations and checks use the trusted workspace header and `POST` to the same route. MCP exposes the same operations through `viral_hit_comfy_connection` with a `request` object:

```json
{ "request": { "action": "read" } }
{ "request": { "action": "check", "url": "http://127.0.0.1:8188" } }
{ "request": { "action": "save", "url": "http://127.0.0.1:8188", "expectedRevision": 0 } }
```

HTTP takes the inner request object. Use the actual revision from the latest read, and use `url: null` to disconnect. A stale save returns HTTP 409. The endpoint is for a trusted local workspace; public multi-user administration and per-project routing are not implemented. Cloud Router credentials still use the server-side `COMFY_API_KEY` environment variable.
